# Walk iOS 全 App 模拟器 UI 巡检报告

- 日期：2026-09-12
- 环境：iPhone 17 Pro（iOS 26.5）模拟器，Walk Debug 构建（walkios main 工作区，含未提交修改）
- 方式：模拟器逐页人工巡检 + idb 点击/滑动 + 逐页截图
- 截图：本目录下 `01-*.png` ~ `26-*.png`
- 范围：首页、行程详情（含装备/天气/取消确认）、路线发现/全部路线/搜索、路线详情（含立即出发流程）、我的（装备/清单/全部行程/账户/个人资料/登录）
- 说明：仅巡检，未改任何代码。部分异常由 Mock 数据缺失触发，已标注。

## 1. 元素被遮挡

| # | 问题 | 证据 |
|---|------|------|
| 1.1 | 行程装备编辑表单：保存失败的错误提示（红色条）被底部固定「保存本次装备」按钮遮挡，只露出一个红色三角一角，用户几乎看不到失败原因 | `06b-equipment-save-error.png` |
| 1.2 | 同一表单内嵌的「取消」按钮被推到屏幕外（AX frame y=860，屏幕高 874），基本不可点；表单保存/取消与底部固定保存按钮职责重叠 | `06-trip-equipment-edit.png` |
| 1.3 | 路线详情：右上「立即出发」+「分享路线」悬浮按钮组在滚动时持续遮挡正文（高海拔预警文字、「起点停车场 · 3,676 m」副标题被盖住；地图上「水源点」标注也被按钮压住一半） | `10/11/12-route-detail-*.png` |
| 1.4 | 行程详情：底部悬浮「取消行程」按钮遮住滚动内容（D3 卡片、装备卡下缘） | `02b-trip-detail-top.png`、`04-trip-detail-bottom.png` |
| 1.5 | 滚动穿透：行程详情、路线详情滚动时正文文字直接顶到状态栏，与时间/电量图标重叠，无 scroll edge 渐隐或材质隔离 | `03-trip-detail-mid.png`、`12/13-route-detail-*.png` |
| 1.6 | 「取消行程」确认对话框背景过透，后方 GearRing 图表透出形成绿色斑块，对话框可读性下降 | `09-cancel-trip-confirm-dialog.png` |

## 2. 不合时宜的交互

| # | 问题 | 证据 |
|---|------|------|
| 2.1 | 退出登录无任何二次确认，点击立即登出（破坏性操作） | `24-profile-logged-out.png` |
| 2.2 | 行程详情隐藏 Tab 栏后，「取消行程」悬浮按钮恰好占据 Tab 栏位置；巡检中两次想切 Tab 都误触弹出了「确认取消行程」对话框——误触成本极高 | `09-cancel-trip-confirm-dialog.png` |
| 2.3 | 行程详情页内在内容区上滑滚动会被识别为返回手势直接 pop 回首页，滚动与返回手势冲突（巡检中实测发生） | `02/03-trip-detail-*.png` |
| 2.4 | 装备清单创建：内联表单只有「取消」在输入框旁，「保存清单」固定在屏幕最底部，两者相距约一屏，操作动线断裂 | `20-add-equipment-form.png` |
| 2.5 | 保存失败时界面看似"无反应"（错误被按钮盖住，见 1.1），无 toast/反馈 | `06b-equipment-save-error.png` |
| 2.6 | 登录手机号输入框未指定数字键盘类型（弹出英文 QWERTY） | `25-login.png` |
| 2.7 | 「进行中优先」「按出发日期排序」绿色标签视觉上像可点按钮，实为静态排序说明 | `21-trip-calendar.png` |

## 4. 其他问题（文案 / 数据一致性）

| # | 问题 | 证据 |
|---|------|------|
| 4.1 | 技术词汇直接暴露给用户：`quye-import` 数据来源标签；`trailhead / pass / scenery / regular / warning / notice` 英文枚举未映射中文 | `10/12/13` |
| 4.2 | 错误文案泄漏内部实现：生成失败页「没有把失败当作空装备或不可生成路线。」不可读；装备保存失败「未找到 Mock：PATCH /trips/trip-1/...」暴露 Mock 细节 | `14-depart-flow-1.png`、`06b` |
| 4.3 | 实现说明式文案：「当前行程和历史行程在同一页面分组展示」「初始状态不展示默认结果」「热点仅展示日期分布」「行程日历，数据不完整」 | `21/16/17` |
| 4.4 | 术语不当：「脱敏手机号」应直接叫「手机号」；「请输入 E.164 国际格式手机号」对普通用户过技术化 | `23/25` |
| 4.5 | 重复文案：行程详情「行程采用版本已冻结」标题与卡内首行重复；天气页三张「重要提醒」卡各带一次标题 | `02b/04` |
| 4.6 | 数字/单位不一致：`2,300 m`（首页）vs `2300 m`（详情）；编辑表单「单位：克」输入 1800，卡片显示 `1.8 kg`；我的装备空态显示 `0 g` | `01/02b/06/17` |
| 4.7 | 日期格式不一致：列表「8月25日—8月27日」vs 详情「2026-08-25–2026-08-27」 | `21/02b` |
| 4.8 | `2.48` 徽章在路线列表与详情反复出现，无单位无解释，含义不明 | `08/10/15` |
| 4.9 | 天气图例「最低温」与「降水」同为蓝色，难区分；「更新时间有效」不是信息性文案 | `04/07` |
| 4.10 | 首页天气空态「未提供天气摘要」偏 API 口吻 | `01-home.png` |

## 5. 说明

- Mock 数据只有 1 条路线、1 个行程，多数页面大量留白属数据问题，未计入 UI 缺陷。
- 搜索输入中文受 idb 限制未验证结果态，仅覆盖初始态与错误态。
- 建议优先级最高：1.1（错误提示被遮）、2.1（退出无确认）、2.2（取消行程误触）、1.3（悬浮按钮遮正文）、4.2（技术错误文案外泄）。
