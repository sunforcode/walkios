# Walk 设计总纲

> v0.1 · 2026-09-11 · 本地设计提案，尚未替代现行 UI 规范
>
> 面向产品、设计与研发，统一整个 Walk 的视觉与交互判断。本文定义整体设计语言，不规定具体页面布局。

## 1. 设计定位

**让 Walk 像一件精心设计的现代户外装备：有山野的吸引力，有工具的清晰度，有拿在手里就想出发的感觉。**

总体方向：**沉浸式山野、精密的信息表达、轻盈而连续的交互。**

气质关键词：自然、利落、鲜明、可靠、有探索欲。

Walk 的核心体验仍服务于个人徒步行程。视觉表达要让人愿意探索，也要让人容易理解自己的准备与安排；品牌个性贯穿其中，事实和操作始终清楚。

## 2. “炫酷”的具体含义

Walk 的表现力来自三件事：

1. **画面有纵深。** 场景、信息与操作形成清楚的前后关系，用户能感到山野的尺度。
2. **信息有力量。** 标题、数字、路线和图表拥有鲜明层次，重要内容一眼可见。
3. **动作有连贯性。** 点击、展开、返回与切换能说明对象去了哪里、状态怎样变化。

新增视觉效果时，应能指出它改善了哪一项。装饰不持续争夺注意力；动效不延迟用户完成操作。

发生冲突时，按以下顺序取舍：**事实与可读性 → 理解与操作效率 → 品牌一致性 → 视觉戏剧性。**

## 3. 品牌识别

### 3.1 颜色与标志

从目前选择的**森林绿与米白石标**方向继续发展：森林绿建立品牌记忆，米白带来温度，石标表达出发与方向感。标志的具体轮廓仍可精修。

标志在小尺寸下保持单一、清楚的轮廓；不依靠阴影、纹理或发光识别。图形的轻微不对称可以保留，整体重心应稳定。

### 3.2 图形语汇

优先从山脊、路径、等高线和路标中提取图形语言。每个画面选择一个主要意象，避免同时堆入山、树、帐篷、指南针等多个符号。

图形的线条、转折与间距保持同一套节奏。装饰性的路径或等高线应与真实地图、轨迹、海拔数据明显区分，不承载导航含义。

## 4. 色彩方向

**深色建立沉浸感，自然影像提供变化，少量明亮绿色指向重点。**

以下色值仅用于讨论视觉关系，不构成新的生产 Token；实际取值与语义仍由现行 Design Token 统一管理。

| 角色 | 方向样本 | 用途原则 |
|---|---|---|
| 品牌森林绿 | `#287658` | 标志与品牌识别，可用于有限的大色块 |
| 森林黑 | `#07130F` | 沉浸背景，让影像、文字与路线突出 |
| 米白 | `#FFF3DF` | 标志与少量品牌强调，带来温度 |
| 薄荷绿 | `#8BD6AD` | 主交互、选中态与需要强调的路线信息 |
| 中性灰绿 | `#B8C2BD` | 次级信息，保证阅读清晰 |

使用原则：

- 同一视野建立一个明确的主强调，避免所有按钮、数字和标签一起高亮。
- 相邻表面主要依靠明度和空间区分；描边与阴影作为辅助。
- 风景保留本来的天空、岩石、植被与光线，避免统一覆盖浓绿滤镜。
- 警告、错误、信息与行程状态继续使用稳定的语义颜色，并同时给出文字或形状提示。
- 品牌绿、选中态与“情况良好”不能混为一谈，天气或数据不确定时尤其如此。

深色是本次方向提案的主表达。浅色外观的产品支持范围另行决定；高对比、降低透明度等辅助设置下，信息和操作应保持完整。

## 5. 字体与信息层次

字体气质是**干净、坚定、准确**。中文和常规文字优先采用清楚的系统无衬线风格；精密感主要通过数字对齐和版式建立。

- **标题有尺度差。** 允许关键标题形成视觉重心，其余标题服从内容层级，不把所有标题都做大、加粗。
- **正文有舒适度。** 连续阅读内容使用稳定行高和充足留白，重要说明不降为装饰性小字。
- **数字有秩序。** 需要比较、变化或纵向对齐的数值采用等宽数字；单位从属于数值，但必须清楚。
- **标签有节制。** 标签用于快速识别分类和状态，不把每个名词都装进胶囊。
- **放大后结构仍成立。** 字号放大时允许换行、增高或重排，避免通过缩字和截断保住原来的构图。

字号、字重与间距统一通过语义层级管理，不允许各处独立“调到好看”。

## 6. 空间、形状与材质

### 6.1 空间

空间表达遵循**场景层 → 信息层 → 操作层**的关系。这是视觉层级，不要求每个画面同时具备三层。

先用对齐、留白、大小与明度建立秩序，再决定是否需要容器。内容确实构成独立对象或独立操作区域时才使用卡片；避免连续的卡片套卡片。

### 6.2 形状

整体轮廓柔和，内部排布利落。沿用统一的间距和圆角家族，允许大表面与小控件有等级差异。圆角不能让所有元素都变成同样的软胶囊。

分隔线轻而必要。边框说明边界，阴影说明高度，二者都不成为每个容器的默认装饰。

### 6.3 材质

- **稳定实底**承载正文、数据、表单与需要长时间阅读的信息。
- **半透明或玻璃材质**用于确实浮在内容上方的导航、工具与临时控制，帮助保留上下文。
- **光感与细微高光**集中在焦点、选中态或短暂反馈中，避免静态内容持续发光。

透明背景变化时文字依然可读；需要时使用稳定遮罩或实底。材质效果退化后，交互层级依然成立。

## 7. 影像、地图与数据图形

### 7.1 影像

影像强调真实的地形尺度、光线与空气感。优先选择主体明确、有远近层次、能为文字留出位置的素材；避免过饱和滤镜和与目的地无关的装饰图。

当影像与一条真实路线关联时，应有明确的内容对应关系。缺少可用影像时采用诚实的无图表达，不用虚构风景冒充实际地点。

### 7.2 地图与数据

专业感来自数据之间清楚的关系：数值与单位对应，颜色与图例对应，路线与点位对应，时间与行程上下文对应。

- 真实地形、轨迹、海拔和天气必须使用有依据的数据；缺失部分明确表达缺失。
- 装饰曲线不能伪装成实测图表，动画不能制造未发生的进度。
- 同一数据对象在不同表达中的名称、颜色语义和状态保持一致。
- 图形应帮助判断和比较，支持读数；不依靠立体透视或夸张比例制造视觉冲击。

3D、视差、路线预演等形式可作为未来表达手段，采用前应确认真实数据与产品范围支持；本总纲不将这些能力新增为必做功能。

## 8. 动效与触感

动效的性格是**短、顺、跟手**。

| 动效类型 | 主要职责 | 表达原则 |
|---|---|---|
| 即时反馈 | 告诉用户操作已被接收 | 轻微变化，快速响应 |
| 对象过渡 | 说明对象展开、收起或转移的位置 | 保持方向、起点和空间连续性 |
| 状态变化 | 说明选中、完成或局部内容更新 | 动作范围与变化范围一致 |
| 场景动效 | 增强景深或空间感 | 低幅度，只在必要时出现 |

常规操作不使用明显的大幅弹跳；弹性可用于少量具有直接操控感的动作。避免同时启动多个方向、多个节奏的动画。

触感用于有意义的选择、确认或状态边界，不把普通浏览变成持续振动。声音不是完成操作的必要条件。

遵循用户的减少动态效果偏好。动画可中断，等待过程诚实，用户无需看完动画才能继续。

## 9. 交互与表达的共同底线

Walk 的品牌声音像一位熟悉户外的同行者：清楚、平静、具体。

- 操作名称说明结果；重要操作与当前对象的关系明确。
- 数据来源、时间与不确定性在需要判断的位置可见。
- 公共路线事实、个人行程结果与长期个人装备保持身份清楚；视觉整合不抹去它们的区别。
- 空、加载、错误、缺失、过期与不可用分别表达，不用同一动画或灰色占位混过去。
- 局部问题在局部说明，避免不必要地遮断整段体验。
- AI 的价值体现为组织好的个人行程；内部推理、工具调用和执行流程不成为品牌装饰。
- 不使用绝对化的安全保证，也不以热情文案掩盖信息不足。

遵守现行导航、滚动、安全区、焦点、Dynamic Type 和触控规范。设计表现力不能依赖过小的按钮、低对比文字或隐藏手势。

## 10. 统一的取舍规则

当设计出现分歧时，优先采用右栏的判断：

| 分歧 | Walk 的判断 |
|---|---|
| 是否再加一种效果 | 先确认它能改善空间、理解或反馈 |
| 是否再加一个卡片容器 | 先确认内容是否确实具有独立边界 |
| 是否使用更鲜艳的颜色 | 先确认它要强调的对象与语义 |
| 是否使用大图 | 先确认素材与内容相关且不会牺牲判断信息 |
| 是否使用很小的数字与标签 | 保证关键内容在常规阅读和字号放大时都清楚 |
| 是否为了整齐隐藏缺失信息 | 保持缺失与不确定性可见 |
| 是否为了炫酷增加新能力 | 回到产品范围判断，不由视觉需求直接扩张功能 |

## 11. 设计评审标准

任何方案提交评审时，应能具体回答：

1. 去掉品牌名称后，色彩、图形和排版是否仍具有 Walk 的一致气质？
2. 主要内容与主要操作是否能迅速识别？
3. 表面之间是否有清楚的前后与轻重关系？
4. 图像、图表与地图是否真实对应当前内容？
5. 动效是否帮助理解操作与状态变化？
6. 放大字体、降低透明度和减少动效后，重要内容与操作是否完整？
7. 未知、过期、错误和待核验是否诚实表达？
8. 去掉一项装饰后，如果理解与识别没有变差，是否可以删除它？

通过标准以可观察的效果为依据；“高级”“酷”“像某个 App”不能单独构成验收理由。

## 12. 文档归属与后续展开

本文是设计方向提案。现行产品事实、UI 合同和 Token 继续由既有权威文档管理。

若采纳本方向，应在同一套 UI 规范中逐步落实为设计原则、语义 Token、通用形状与材质规则、动效规则以及视觉验收依据。具体页面在这些共同规则下展开，不另立一套风格。

本次仅形成本地草案，不增加产品能力、不更新线上设计、不改变现有生产实现。
